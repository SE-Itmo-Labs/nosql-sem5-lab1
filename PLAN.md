## 3. Модель данных и представление в «ключ — значение»

Обоснование: уведомления и категории — естественные записи вида «ключ → JSON-строка»,
у Kasabus/Object нет вложенных отношений, поэтому схема «ключ — значение» подходит без нормализации.

Предлагаемая схема ключей:
- `notification:{id}` → JSON уведомления (клиент, заголовок, текст, категория, статус, время создания).
- `notification:user:{userId}` → set (sorted set) ID уведомлений клиента — для сценария «отправка уведомлений» и выборки по клиенту.
- `category:{id}` → JSON категории (справочник, кэшируется).
- `block:{resourceId}` → маркер временной блокировки ресурса (TTL).
- `lock:{resourceId}` → маркер распределённой блокировки (REDIS-SET NX EX).
- `notification:seq` → инкрементный счётчик ID уведомлений (`INCR`).

## 4. Сценарии (обязательный + дополнительные параметры варианта)

### 4.1 Обязательный сценарий — отправка уведомлений
- REST: `POST /api/notifications` (создать и «отправить» уведомление), `GET /api/notifications/user/{userId}`, `GET /api/notifications/{id}`.
- Создание: `INCR notification:seq` → запись JSON → добавление ID в список клиента.
- Чтение списка уведомлений клиента через Sorted Set — получение деталей по ключам.

### 4.2 Временное хранение — TTL
- `POST /api/blocks` — установить временную блокировку ресурса с TTL (например, бронь места в кинотеатре на 5 минут).
- `GET /api/blocks/{resourceId}` — проверить активность блокировки.
- Реализация: `SET block:{resourceId} ... EX n`. Автоудаление ключа по TTL.
- Обосновать выбор TTL как механизма «application-level expiration»/lease для Redis.

### 4.3 Кэширование — справочник категорий
- `GET /api/categories` — отдавать из кэша.
- Стратегия: `cache-aside` — при промахе читать источник (БД/коллекция), класть в Redis с TTL, инвалидация при создании/изменении категории.
- Аннотация `@EnableCaching` / `@Cacheable` ИЛИ ручная работа через `RedisTemplate` (ручная — приоритет, т.к. нагляднее для лабораторной).

### 4.4 Атомарный механизм — распределённая блокировка
- Реализовать блокировку «ресурса» (например, отправка/обработка уведомления, работа с местом).
- Redis: `SET lock:{resourceId} <token> NX EX <timeout>` — только один владелец.
- Освобождение через сравнение токена (Lua-скрипт `GET` + `DEL`) — защита от снятия чужой блокировки.
- Показать гонку: два параллельных запроса — второй получает отказ/ожидание.
