# Архитектура frontend

Frontend построен на Nuxt и разделен по ответственности. Страницы связывают
готовые блоки, компоненты отображают данные, composables управляют состоянием,
а слой `services/api` изолирует транспорт.

## Структура

```text
nosql-sem5-lab1-frontend/app/
├── assets/css/                  # дизайн-токены и общие стили
├── components/
│   ├── feature/                 # карточки возможностей на главной странице
│   ├── layout/                  # sidebar и верхняя панель
│   ├── catalog/                 # фильмы, сеансы и интерактивная схема мест
│   ├── blocks/                  # создание, поиск и состояние временной брони
│   ├── categories/              # справочник, редактор и cache inspector
│   ├── consistency/             # форма и результат исследования репликации
│   ├── locks/                   # конкурирующие запросы к Redisson lock
│   ├── notifications/           # форма, фильтры, статистика, список и карточка
│   └── ui/                      # общие заголовки и состояния страниц
├── composables/
│   ├── useApi.ts                # выбор источника данных
│   ├── useAuth.ts               # пользовательская сессия
│   ├── useCatalog.ts            # загрузка афиши, фильма, сеансов и мест
│   ├── useBookingSelection.ts   # выбранный сеанс и места оформления
│   ├── useCategories.ts         # CRUD и наблюдение за cache-aside
│   ├── useConsistencyExperiment.ts # запуск эксперимента primary/replica
│   ├── useDistributedLock.ts    # две параллельные попытки захвата lock
│   ├── useTemporaryBlocks.ts    # жизненный цикл ключа с TTL
│   └── useNotifications.ts      # состояние и действия раздела уведомлений
├── config/navigation.ts         # единая карта разделов
├── constants/apiEndpoints.ts    # URL backend в одном месте
├── layouts/                     # гостевой и защищенный каркасы
├── middleware/                  # проверка доступа к маршрутам
├── pages/                       # короткие компоненты маршрутов
├── services/
│   ├── api/http/                # настоящий REST-клиент
│   ├── api/mock/                # локальные реализации по доменам
│   └── auth/                    # хранение сессии
└── types/api/                   # контракты по предметным областям
```

## Источники данных

Страница получает один интерфейс `ApiClient` и не знает, какая реализация
работает внутри:

- `mock` хранит демонстрационные данные в Nuxt state;
- `real` отправляет запросы в Spring Boot;
- автоматического отката с `real` на `mock` нет, чтобы не скрывать ошибки.

Режим выбирается переменной `NUXT_PUBLIC_API_MODE`. Все URL собраны в
`apiEndpoints.ts`, а структуры запросов и ответов — в `types/api`.

## Правила декомпозиции

- Страница отвечает за композицию экрана, а не за детали формы или таблицы.
- Компонент решает одну визуальную задачу и общается событиями и props.
- Асинхронные операции предметного раздела находятся в отдельном composable.
- Mock и HTTP реализации повторяют общий контракт и не ветвят шаблоны страниц.
- Комментарии объясняют причину решения или неочевидное поведение, а не
  пересказывают следующую строку кода.

## Афиша и выбор мест

Клиентский путь состоит из трёх маршрутов:

- `/movies` показывает афишу карточками `MovieCard`;
- `/movies/{id}` показывает фильм и будущие сеансы через `ScreeningList`;
- `/screenings/{id}` загружает схему зала и позволяет выбрать доступные места в
  `SeatMap`.

`useCatalog` одинаково работает с настоящим REST API и mock-данными.
`useBookingSelection` хранит выбранные идентификаторы сеанса и мест между
переходами. Каждая страница отдельно показывает загрузку, отсутствие данных и
ошибку. На текущей итерации выбор остаётся локальным; серверное удержание с TTL
подключается следующей итерацией.

## Роли в интерфейсе

Единая конфигурация навигации помечает разделы аудиторией `all` или `admin`.
Sidebar и главная страница фильтруют пункты по роли текущего пользователя.
Middleware `admin` не допускает клиента на страницы категорий, распределённой
блокировки и согласованности. Форма ручной отправки уведомления показывается
только администратору и позволяет выбрать получателя; история уведомлений
остаётся клиентским экраном.

## Раздел уведомлений

Раздел реализует обязательный сценарий лабораторной работы:

- загрузку истории текущего клиента;
- поиск и фильтрацию по категории и статусу;
- агрегированную статистику;
- административную отправку нового уведомления выбранному клиенту;
- отметку о прочтении и удаление в mock-режиме (backend этих методов пока не
  предоставляет);
- loading, empty и error состояния;
- постраничную навигацию.

## Справочник категорий

Раздел наглядно разделяет постоянный источник и Redis-кэш:

- список загружается обычным endpoint справочника;
- контрольный запрос категории показывает `DATABASE` при cache miss;
- повторный запрос показывает `CACHE` и оставшийся TTL;
- создание, изменение и удаление отражаются в общем mock-состоянии;
- после изменения старый результат инспектора сбрасывается, поскольку backend
  должен инвалидировать соответствующий ключ.

## Временная блокировка

Раздел демонстрирует временный Redis-ключ для бронирования ресурса:

- создание ключа с владельцем и настраиваемым TTL;
- проверку произвольного `resourceKey`;
- обратный отсчёт по серверному `expiresAt`;
- повторный GET после истечения для подтверждения ответа `404`;
- досрочное освобождение через отдельный DELETE-запрос.

## Распределённая блокировка

Экран отправляет два параллельных запроса на один `resourceKey`. Backend
выполняет критическую секцию под `RLock`: один ответ получает
`acquired: true`, второй показывает отказ без изменения HTTP-статуса. Время
удержания ограничено теми же пределами, что и backend: от 0 до 10000 мс.

## Согласованность primary/replica

Форма позволяет выбрать узел контрольного чтения и один из двух режимов:

- `EVENTUAL` — чтение выполняется без ожидания репликации;
- `WAIT_FOR_REPLICA` — перед чтением backend вызывает Redis `WAIT`.

Результат показывает записанное и прочитанное значения, фактический узел,
число подтверждений и отдельные длительности записи, ожидания и чтения.

Подробнее о соответствии frontend и backend см. в
[контракте REST API](API_CONTRACT.md).
